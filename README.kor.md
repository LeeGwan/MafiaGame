Flect Security Module: 커널 모드 보안 학습용 프로젝트
Flect Security Module은 유저 모드에서 흔히 사용되는 방어 기법들을 커널 모드에서는 어떻게 구현할 수 있을지 궁금하여, 그 개념들을 커널 환경으로 이식해 본 개인 학습용 프로젝트입니다. 언리얼 엔진 클라이언트와 커널 드라이버, 그리고 간단한 서버 통신으로 구성된 기초적인 보안 연구 결과물입니다.

🛠 아키텍처 개요
본 프로젝트는 "유저 모드의 방어 개념을 커널 레벨로 확장"하는 것에 목적을 두었습니다.

Kernel Driver: Ring 0 환경에서 프로세스를 보호하고 정보를 수집하는 기본적인 커널 드라이버 구조를 구현했습니다.

Client Core: 언리얼 엔진 환경에서 드라이버와 통신하며 보안 모듈을 구동하는 역할을 합니다.

Server: 클라이언트의 무결성 검증 데이터를 간단히 수신하고 로그를 저장하는 역할을 합니다.

🛡 주요 구현 내용
1. 프로세스 보호 (Handle Stripping)
ObRegisterCallbacks 적용: ObRegisterCallbacks를 사용하여 프로세스 핸들 생성 시 호출되는 커널 콜백의 기본 구조를 학습하고 적용했습니다.

권한 제어: 유저 모드에서 흔히 차단되는 메모리 쓰기(PROCESS_VM_WRITE) 등의 권한을 커널 레벨에서 핸들 생성 시점에 0으로 만드는 방식을 구현했습니다.

2. 코드 무결성 검증 (Code Integrity)
CRC32 메모리 스캔: 프로세스 메모리 영역을 256바이트씩 나누어 CRC32 해시 값을 계산하고, 메모리 변조를 간단하게 탐지하는 루틴을 구현했습니다.

주기적 모니터링: 시스템 스레드를 생성하여 10초마다 메모리를 재검사하도록 만들었습니다.

3. 하드웨어 정보 수집 (HWID)
물리 메모리 접근: 윈도우 API가 아닌 커널 레벨에서 직접 물리 메모리(MmMapIoSpace)를 매핑하여 SMBIOS 정보를 파싱하는 방법을 공부했습니다.

💻 프로젝트 구성요소
1. Kernel Mode Driver
ProcessGuard: 프로세스 핸들 생성 시 권한을 제어하는 콜백 로직.

CRC Engine: CRC32를 이용한 메모리 무결성 검사 및 스레드 루틴.

GetHardware: SMBIOS 테이블 직접 파싱 및 정보 수집.

2. Client Core (Unreal Engine)
Communication: DeviceIoControl을 통해 유저 모드와 커널 모드 간의 데이터를 주고받는 기초 통신 인터페이스.

3. Server
클라이언트로부터 전달받은 하드웨어 식별자 및 메모리 해시 데이터를 수신하는 서버 모듈.

🚀 학습 경험 및 소회
개인 학습: 커널 모드 프로그래밍과 드라이버 개발의 기초를 다지기 위해 시작한 프로젝트입니다.

실험적 구현: 유저 모드 보안 기법들을 커널로 가져오면 어떻게 동작할지 직접 설계하고 구현해보며 많은 것을 배웠습니다.

성취: 완벽한 안티치트라기보다, 커널 수준의 제어와 안정적인 시스템 프로그래밍(동기화, 예외 처리 등)을 경험해 본 것에 의의를 둡니다.

"이 프로젝트는 윈도우 커널 프로그래밍에 입문하며, 배운 지식을 바탕으로 직접 보안 모듈을 만들어 본 과정입니다."
